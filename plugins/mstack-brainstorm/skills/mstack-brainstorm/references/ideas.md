# Ideas mode

Read this when the user asks for ideas or options instead of bringing an idea of their own ("give me ideas for X", "what could we do about Y"). The mode has three stages. Do not mix them: judging while generating makes the first plausible idea win.

## 1. Generate

1. You generate the ideas yourself. Switch to prompting the user for their own ideas only when the user asks for that ("help me think of ideas", "ask me questions").
2. Before the first idea, state the subject in one line, as a question the ideas answer ("How might a new user get to their first saved list in the first minute?").
3. Use at least two different ways of generating, and say which ones you used in one line. Pick from these, or use another that fits the subject:
   - **Take a limit away.** Drop one constraint (time, money, the current platform), see what becomes possible, then walk back to what can be done.
   - **Borrow from elsewhere.** How does a different field, product or everyday situation handle the same problem?
   - **Make it worse.** List ways to make the problem worse, then turn each one around.
   - **Change who it is for.** How would a first-time user, an expert, an admin or a skeptic want it to work?
   - **Split it up.** Break the problem into parts and find an idea for each part on its own.
   - **Change one piece.** Replace, combine, enlarge, shrink, remove or reverse one part of what exists today.
4. Give at least six ideas in the first message, each in one or two lines. The first few ideas are usually the obvious ones; keep going past them, and switch to another way of generating when one stops producing. They must differ in kind, not only in detail: if most of them are variants of one idea, generate again with another way.
5. In this stage, never rank, score, recommend, discard or call one idea the best. No "my favorite", no ordering by quality. Say how many ideas there are and ask whether to generate more or to move on to choosing.

## 2. Choose

Start this stage when the user says they are ready to choose, or asks which idea is best.

1. Group close ideas together, then give a short list of three to five. For each idea on the list give:
   - its biggest unknown: the assumption that, if wrong, sinks it (about who wants it, whether the problem is real, whether it can be built, whether people would find and use it);
   - the cheapest way to settle that unknown: a question to ask someone, a look at existing data, a throwaway prototype, a one-day trial.
2. Name the ideas set aside, in one line, so the user can pull one back.
3. You may say which idea you would pick and why, now that generating is over.
4. End with one question asking which idea to take forward.

## 3. Continue

1. When the user picks an idea, go back to the default mode with that idea as the request: restate it, say what you know, and ask the one question that matters most. The picked idea goes into the brief under Approaches considered or Intent as the user's decision.
2. When the user picks none, ask what was missing from the list. Write no brief. Offer to generate again from what they say.
3. A list of ideas never ends the conversation without a next step: either a pick, a new round, or the user stopping.
